# Can we observe phase timing without changing GEMM performance?

We measure a single middle reduction stage inside the original GEMM, retaining its inputs, output checks, memory layout, matrix operations, and both necessary barriers. One stage processes 32 reduction elements. Four builds compare no timestamps, two timestamps around the whole stage, three timestamps splitting staging from computation at the original barrier, and three adjacent timestamps at stage entry. The adjacent reads measure clock-read spacing; they cannot reproduce the scheduling impact of separated reads.

Every warp records its clock readings for that stage. Staging includes its producer-consumer barrier; computation includes the barrier that protects shared-memory reuse. These are elapsed phase intervals under scheduling and contention, not isolated hardware latencies. Timestamp instructions and compiler barriers can perturb execution. We therefore inspect compiled matrix work, register use, spills, and resident-block limits and compare ordinary whole-kernel timing with the uninstrumented build.

Two existing workloads and two tiles are run in two paired repetitions with reversed build order. All outputs are independently checked against cuBLAS, and every timed launch uses the existing cache sweep. We accept a phase measurement for model calibration only if the instrumented build is correct, spill-free, has unchanged residency, and changes median whole-kernel time by at most 5% in both paired runs. Otherwise the result is a diagnostic limitation, and its phase values are not inserted into the model. This distinguishes genuine phase observation from a materially altered kernel more efficiently than fitting new costs to instrumentation-biased data.

Clock, memory-clock, power, and temperature snapshots accompany each execution. Clocks are not locked, and snapshots do not prove constant conditions. Hardware caches remain active; explicit L2 modeling and MILP refitting remain excluded. GPU 7 is used only after an idle check. Source, raw readings, timing repeats, and compiled instructions are retained.

The first measurements showed a large instrumentation slowdown for the larger tile, even with unchanged residency. A bounded repair removes the empty compiler memory barriers while retaining the original synchronization barriers and clock reads. We repeat the larger tile on both workloads against a freshly timed baseline. These measurements are admissible only after checking timestamp placement in compiled instructions: without compiler barriers, source positions alone do not establish that reads bound the intended operations. The same 5% runtime criterion and resource checks apply, and disagreement with the whole-stage control is reported rather than silently subtracted.
